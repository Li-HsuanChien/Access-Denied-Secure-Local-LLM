# Frontend guidance

Follow the [PRD](../../../../docs/product/PRD.md) and [SDD](../../../../docs/architecture/SDD.md), including answer sections, citation expansion, Library publication states, History/settings behavior, accessibility, and one-question-at-a-time interaction.

The canonical frontend uses React/TypeScript/Vite, preserving the observed Open WebUI interface under [ADR 0004](../../../../docs/architecture/decisions/0004-react-frontend-parity.md). The Svelte source was removed from the active workspace at cutover; Git history and accepted baseline evidence preserve comparison and rollback. Put user-facing code by feature under `lib/features/<feature>/` and keep `src/react/` composition and routes thin. Keep components focused on presentation and interaction; evidence classification, publication safety, citation validity, and persistence decisions belong to backend workflow interfaces.

Keep UI tests beside or within the feature they cover. Test visible states, keyboard access, focus, semantic labels, contrast, and progress/error announcements. Do not introduce remote assets, telemetry, or network-backed behavior.

Read the [React contracts and ownership matrix](../../../../docs/development/react-migration/react-contracts.md) before changing shared interfaces. Use AppProviders hooks for preferences, answering and Library lifecycle; do not create competing page-level host requests or duplicate history saves. Chat presentation edits never mutate validated answer payloads. Chat and History retain distinct markup. Preserve original assets, fonts, CSS specificity and visible actions, with only the documented safety exceptions. Every Markdown, diagram and HTML/SVG preview path must block model code execution, external navigation and remote/arbitrary loopback resource loads.
