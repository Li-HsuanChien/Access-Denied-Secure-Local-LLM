Routing uses `src/react/routes/navigation.ts` and `useNavigation()`, with no router package. `/` and `/qa` mount the same Chat. `/library`, `/history`, `/settings` mount their feature. `/c/:id` replaces the URL with `/` without attempting unsupported upstream APIs. Unknown routes also settle at `/`. `navigate('/', {newChat: true})` resets Chat even on the same root URL. Browser Back/Forward updates the route via `popstate`; entering Chat gets a new `chatEpoch`. ## Shared runtime and hooks

`src/react/providers/index.ts` exports `AppProviders`, `createAppRuntime`, `createDefaultServices`, `useServices`, `useNavigation`, `usePreferences`, `useAnswering`, `useLibrary`, and `readSavedAnswer`. Framework-neutral exported types live in `src/lib/features/react-contracts/`. `AppProviders` wraps the route tree once. Its default runtime survives route/provider remounts. Tests supply `runtime={createAppRuntime(fakeServices, window)}`; no query-string or window-global fixture switch enters production.

`AppServices` injects the existing Answering, History, Library and Settings clients plus `createId` and `now`. Production defaults remain `http://127.0.0.1:8765`; tests may intercept transport or inject fixtures. The existing answering client still validates loopback destinations, disallows redirects/credentials and validates envelopes and backend-owned `answer.schema.json`. Do not weaken that validation to route tests to the disposable host. The other existing workflow clients retain their fixed loopback transport. Browser fixtures can intercept those exact requests and forward only to the authorized disposable host 8766; the user's host 8765 is untouched during migration QA.

Providers expose cached immutable snapshots through React's [useSyncExternalStore](https://react.dev/reference/react/useSyncExternalStore). No request starts in component render. Repeated mount effects may read but never initiate an answer/publication. Async operations retain their owning runtime independent of subscribed screens. Provider tests exercise public commands, not React internals.

### Bundled localization parity

The original active root calls `initI18n()` before its initial host refresh. Native shell/chat/renderer labels use bundled i18next catalogs even though there is no exposed language picker. React preserves this through `src/react/i18n/` and the entry bootstrap. `import { useI18n, translate, initReactI18n } from '@/react/i18n'`: `useI18n()` returns `{t, language}`; `t(key, options?)` and `translate(key, options?)` return text using the same exact original keys/interpolation names. Options are a framework-neutral record of primitive values. The hook subscribes to initialization, loaded resources and language events; callbacks can call `translate`. Bootstrap waits for locale initialization, then mounts the existing application. If initialization rejects, it still mounts with English/key fallback, without a new loading/error interface or unhandled rejection.

Detection order is query `lang`, existing localStorage `locale`, then navigator languages. The detected language is cached in `locale` and assigned to `document.documentElement.lang`; do not add a language control or direction change. Preserve the original fallback map `{fr:['fr-FR'],default:['en-US']}`, including base `fr` using the French catalog while its language attribute remains `fr`. Unsupported locales retain their detected language/cache but use English or key fallback; do not filter with `supportedLngs` or normalize to a catalog name. `keySeparator:false`, `nsSeparator:false`, `returnEmptyString:false` and `interpolation.escapeValue:false` match the original; React renders translated strings as text, not injected HTML. Empty English catalog entries intentionally return the key. Example exact original keys: `1 Source`, `{{COUNT}} Sources` with `{COUNT:n}`, and `Version {{selectedVersion}} of {{totalVersions}}`. Use existing i18next plural/interpolation behavior rather than implementing custom substitutions.

Only translate labels that used `$i18n.t` on the original active path. Feature-owned Library/History/Settings copy, health/general-knowledge header copy, answer-section labels, model name and seeded suggestion text remain their original literal English. Matching a word in a catalog is not evidence that its original control translated it. Feature owners wire their own labels using the shared hook; no duplicate locale detector or per-feature catalog copy.

Retain `src/lib/i18n/locales/*/translation.json` and the framework-neutral `src/lib/i18n/settings-translations.ts` assembler at final cleanup. The bridge loads only entries from a Vite bundled catalog glob, never a URL constructed from a detected language. It uses its own i18next instance and does not import original `src/lib/i18n/index.ts`, `svelte/store` or upstream application stores. Retain the existing locked dependencies `i18next@23.16.8`, `i18next-browser-languagedetector@7.2.2`, and `i18next-resources-to-backend@1.2.1`; no react-i18next dependency is needed. `locales/languages.json` is language-picker metadata, not imported by the active bridge; retain until final closure review if other active imports require it. Resource-loading failure uses existing key fallback; no remote fallback or backend localization operation is introduced.

Focused tests cover query/storage/navigator precedence, caching and html.lang, French/unknown fallback, optional original default-locale behavior, exact interpolation and literal dotted/colon keys, resource failure, mount-after-initialization failure, React subscription and callback translation. Every test denies HTTP fetch. Stage 5 paired browser probes additionally compare French query, German storage and French navigator cases against the preserved original.

### Preferences and shell

`usePreferences()` returns `{state, refresh, setGeneralKnowledge, setHistoryEnabled}`. State includes committed booleans, loaded flags, per-key pending counts and errors. Defaults preserve baseline initial presentation. Writes serialize per preference; the returned host value commits to every subscriber only after success. Failed writes reject and retain the last confirmed value. A write immediately invalidates older reads; a read started before that write cannot restore stale data. Refresh skips a preference with queued writes, and newer reads supersede older ones. It returns the final `PreferenceState` snapshot after its reads settle so callers can inspect current errors without relying on a subsequent React render. A successful read clears that preference's previous error; repeated failures remain visible even when their text is unchanged. Callers catch rejected writes to show existing local error copy. Header/Settings use the same committed general-knowledge value; History/Settings use the same committed persistence value. This deliberately fixes B07 without introducing new controls or notices.

3A owns shell/theme/sidebar state in `desktop-shell/react/`: theme comes from existing `localStorage.theme` (`light`, `dark`, `system`) and media query; desktop sidebar starts open unless `localStorage.sidebar === 'false'`; mobile starts closed. Preserve 768px shell and 700px feature-page breakpoints, 245px sidebar/246px workspace offset and original DOM/visual rules. This state does not require a new persistence layer. Health is read through `useServices().answering.health()`; preserve header and Settings independent reads/Refresh behavior and existing status copy.

### Answer ownership, graph and queue

`useAnswering()` returns `{state: {pending}, ask}`. `ask({sessionId, question, generalKnowledge})` synchronously acquires the app-wide lock before awaiting transport, and rejects overlap with the existing busy error. It calls the existing answering client with only the latest question and current committed general-knowledge flag. No transcript, revision instruction, new request payload field or endpoint is added. It saves the original returned answer once through `history.save(answer.request_id, question, answer)`; disabled persistence returning false is not an error. History failure returns an existing warning while keeping the answer. The immutable answer copy contains all backend fields: citations and per-page spans, evidence, model, collection/prompt versions, timing and errors. The lock remains held through result/history settlement. Do not also call `createOpenWebUIAnsweringAdapter` from React: that would save twice.

3B owns `ChatController` implementation in `answering/react/`, including mount-local message graph, current branch, draft and queue. A `ChatMessage` has parent/child IDs and editable presentation content; assistant messages additionally retain the immutable returned `answer`. Local assistant edit, Save As Copy and CodeMirror Save must never mutate that answer or trigger history saves. CodeMirror Save rewrites its corresponding fence in the transient whole-message content via `ChatAnswerProps.onSaveContent`; AssistantMessageView delegates that to `onSaveEdit(content, false)`, so the edit survives branch switching and whole-message Copy. User Save edits presentation only; user Send creates a sibling question and asks its edited text. Regenerate creates an assistant sibling and re-asks the selected latest question; Try Again/Add Details/More Concise/custom suggestion retain their observed identical wire behavior. Sources continue to reflect the validated answer independently of edited display text. Branch selection, numeric branch input and assistant deletion follow observed behavior.

Ordinary sends during a pending request enter the local queue. Queue Edit removes the item and restores composer text; Delete removes it. Drain FIFO only when the shared lock is free, sampling the committed preference at dispatch. A new session may queue while an older detached session owns the lock but cannot start another actual request. On navigation, New Chat or unmount, discard unsent queued questions and ignore late graph updates using the captured session ID/disposed flag. An already-dispatched answer continues and saves once; it never appears in the new session. The controller must subscribe to shared pending state so its own queue can resume when a different session's request settles.

Cosmetic Stop and overlapping Send now dispatch are omitted. There is no answer cancellation API; fetch abort must never masquerade as cancellation. Hard reload loses this in-memory coordinator and chat graph, as in the baseline; the backend remains authoritative for a request still running across reload. No durable browser job IDs or thread storage are introduced.

### Library lifetime

`useLibrary()` returns `{state, select, confirm, review, publish, cancel, refresh, rollback, leave}`. 3D converts selected browser files to `{name,size,data}` (base64) and renders the existing workflow from shared state. Review, publication and rollback use the existing client. Review still shows the original generic busy panel; no page-count invention or new loading layout. Reject publication without accepted files or required confirmation. The coordinator owns request ID, start time, review needed for restart, progress, 700ms non-overlapping status polls and elapsed clock. Navigation/remount cannot release that state or start another publication. Call `leave()` on actual route exit: idle selection/review resets; an active operation remains reachable on return. Do not call runtime `dispose()` on route unmount.

`cancel()` targets the original request ID, keeps busy true and shows the existing cancellation text. Acknowledgement means cancellation requested, not completion. A false acknowledgement shows the original finishing text. Only the final publication response or terminal status after transport loss releases ownership. An unreachable/invalid-response POST does not prove cancellation: retain ID and continue polling; errors/null status do not release it. Late polls/cancel responses cannot overwrite a finished/different job. The host alone decides activation, failure and cancellation. Hard reload still loses in-memory identity; the existing API cannot discover a request ID after reload. No storage or backend recovery feature is added.

### History

3E calls existing History clients and `readSavedAnswer(await history.open(id))`, validating the saved answer against the same backend schema before rendering. `SavedAnswerRecord` keeps full answer metadata; no Open WebUI graph restoration. History uses its original plain text claims, citation chips and native source `<details>`. Refresh/open/delete/clear and native Clear all confirmation remain mount-local. Persisted data is unchanged. No response edit can rewrite a stored result.

## Rich renderer contract and safety policy

3C exports `AssistantMessageView` accepting `AssistantMessageViewProps` and `ChatAnswer` accepting `ChatAnswerProps`, owning assistant chrome, renderer implementation/CSS, source panel/modal and code/preview state under `answer-renderer/react/`. AssistantMessageView owns assistant markup, Edit/Save/Save As Copy/Cancel UI, Copy/Regenerate/Delete menus and dialogs, and branch controls (one-based index/count). Its callbacks delegate clipboard, regeneration, graph edits/deletion and branch selection to 3B; 3B must not add a second assistant action bar or wrapper. ChatAnswer is the inner rich-content component. `content` is local display Markdown; `citations` are separately validated immutable metadata. `onNavigate` accepts supported `AppPath` only. History does not call ChatAnswer. Preserve inert footnote superscripts, source toggle/chip/modal, Escape/close, quote and page-range labels; there is no source-page image endpoint, so do not invent PDF navigation/highlights (B02/B05).

Preserve observed Markdown, lists/tasks, headings, emphasis, quotes/rules, tables, code, math, Mermaid, inline-data Vega/Vega-Lite, writing colon fences, alerts and multiline details. Port relevant existing tokenizer extensions with baseline parse semantics rather than relying on stock Marked alone. Match one-line raw HTML literal behavior separately. Keep CodeMirror line numbers, language/theme, Collapse, Copy, editable text and Save/Saved local presentation. No Python Run/runtime or arbitrary model code execution. Table Copy uses original Markdown; Export uses original BOM-prefixed quoted CSV semantics. Diagram Copy copies original specification; Download produces sanitized SVG; Reset restores identity transform. Renderer data/config remains untrusted even after the host validates answer structure.

- Markdown links keep text/style. Only exact supported same-origin app paths may navigate. Remove destinations for external, protocol-relative, JavaScript, data, blob, mail, file and unsupported local paths. Remote images retain the observed unavailable presentation and must not even initiate fetches. Do not allow content to request arbitrary loopback URLs.
- Render KaTeX from bundled assets with `trust:false`, bounded expansion, fresh macros per message and no external loaders. [KaTeX documents trust and expansion controls](https://katex.org/docs/options).
- Mermaid uses bundled modules, fixed application-owned strict configuration and no content-supplied init directives/frontmatter configuration or clickable callbacks/links. Do not invoke returned event-binding callbacks. Preserve safe diagram labels and layout; sanitize generated markup and all URL-bearing attributes before mounting/downloading. [Mermaid configuration](https://mermaid.js.org/config/schema-docs/config.html) exposes security settings that untrusted diagrams must not override.
- Vega/Vega-Lite accepts inline JSON data only; reject resource URLs, image marks and navigation hrefs, including nested/computed forms. Install an always-rejecting loader regardless of initial validation. Compile Vega-Lite locally, call `vega.parse(spec, null, {ast:true})`, and supply `expr: expressionInterpreter` to the View. The [official interpreter workflow](https://vega.github.io/vega/usage/interpreter/) avoids `Function` compilation from model expressions. Do not register custom expression functions or load schemas from `$schema`. Sanitize resulting SVG and forbid active links/resources. Test both simple original chart fixtures and hostile nested URLs/expressions.
- HTML Preview remains visually available in an app-created sandboxed `srcdoc` frame. Sandbox has **no tokens**: no scripts, same-origin, forms, popups, top navigation or downloads. Its document starts with restrictive CSP: `default-src 'none'; script-src 'none'; connect-src 'none'; frame-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; style-src 'unsafe-inline'; img-src data: blob:`. Sanitize markup, strip scripts/events, base/meta refresh, form controls/actions, embedded browsing contexts and all navigation/resource URLs; preserve harmless inline styles and safe drawing/text. CSS imports and URL resources must not fetch. Only renderer-owned local data/blob images may be inserted. Do not let model strings inject/replace the CSP. The parent CSP may permit the app-owned preview frame while generic HTML iframes preserve the baseline blocked/error placeholder geometry without creating a fetching frame. No preview messages execute commands or alter host state. SVG Preview retains its observed inline sanitized SVG/panzoom presentation and the same zoom/reset/export controls; do not replace it with an iframe. Strip scripts, events, foreignObject, active links and external/resource URLs before mounting. Allow only safe local fragment references needed for SVG drawing. Apply the same policy to downloaded SVG. Test pointer/zoom behavior independently of HTML frame behavior.

Parent CSP still constrains connections to approved self/loopback endpoints and fonts/assets to local sources. Development HMR is loopback only. Existing AJV may need trusted validation code generation; this does not authorize evaluating model content. Test unsafe content with network recording, including top-level navigation attempts; CSP alone is insufficient to prohibit navigation. Preserve the baseline UI for safe input; only recorded safety cases may differ.

## Production CSS precision

Keep Vite `build.cssMinify: false` and PostCSS `@tailwindcss/postcss` option `optimize: false` in the final configuration. Both the Vite and Tailwind production optimization steps must preserve the source values. The default esbuild CSS minifier changes original decimal shadow alpha (`0.1`) into an eight-digit hex alpha (`26/255`) and lowers direct OKLCH colors to rounded RGB. Paired production captures identified visible pixel differences from these changes. Preserve the source CSS values; JavaScript minification and local asset bundling remain enabled.
