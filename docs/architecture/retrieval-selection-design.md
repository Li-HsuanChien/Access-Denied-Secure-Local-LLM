# Document management and retrieval selection

Implemented design: Knowledge Collections presents individual PDFs with preview, a persistent Use in answers switch, and Delete with explicit confirmation. Uploads add documents to the current library. Identical document IDs (content hashes) replace rather than duplicate the same PDF. The UI no longer exposes snapshot rollback.

Internally the Library still uses atomically activated Chroma snapshots and stable version IDs for answer provenance and cached-source routes. Adding uploads copies unchanged chunk vectors and cached PDFs from the current snapshot, embeds incoming documents only, verifies the combined candidate, then activates it. A failed build leaves the library unchanged. Embedding-model mismatches require republishing with a compatible model rather than mixing vector spaces.

The catalog holds a mutable disabled-document set separately from immutable version manifests/checksums. Toggle writes atomically replace the catalog and do not rebuild embeddings. New documents default to enabled; disabled states follow matching document IDs across additions. Each question opens a store with a frozen allowed-document set. Chroma filters by document ID before top-k selection. With no enabled documents, search returns no evidence without embedding or querying Chroma. Existing insufficient-evidence and general-knowledge behavior applies, and memory remains non-citable.

`library.set_document_enabled {version_id, document_id, enabled}` validates active snapshot membership and returns the saved state. `library.delete_document {version_id, document_id, confirmed}` requires confirmed=true, validates active membership, builds and verifies a snapshot without the deleted document using existing vectors, then activates it. Deletion removes previous snapshots and cached source PDFs so rollback cannot resurrect the deleted PDF. Old chat text/citations remain in history, but a removed cached version can no longer be previewed. Deleting the last document produces an empty library that remains usable for future uploads. This is local application deletion, not secure disk erasure. Sanitized import reports are pruned with retired versions.

The host's nonblocking library/answer job gate serializes publication, toggles, deletes, rollback compatibility calls, and answering. Conflicting requests return busy. The Library also serializes catalog writes. Document selection mutations apply to subsequent questions and never alter an in-flight question. The wire lists each document's enabled state; stale version IDs return an actionable conflict rather than changing the wrong snapshot.

Legacy version-list/rollback operations remain as compatibility seams; Knowledge Collections lists only current documents. The active and previous snapshots are normally retained for existing citation compatibility, except deletion removes all previous snapshots. Previously replaced PDFs that are already absent from the active library are not automatically reimported.
